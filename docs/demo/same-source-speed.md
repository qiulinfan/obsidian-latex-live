## 测量条件

- **本地：**已发布的 LaTeX Live **0.1.1**，安装的三个文件已与 GitHub 发布附件 SHA-256 核对；Obsidian 1.13.7；Apple M5、32 GB 内存；pdfLaTeX / TeX Live 2026。使用默认 **400 ms** 保存延迟与插件的导言区缓存。
- **Overleaf：**已登录的**云端免费账户**；主文件 `main.tex`；pdfLaTeX / TeX Live **2026**；**Normal** 编译模式；开启 **Autocompile**。初始 PDF 与辅助文件已生成。
- 每次测量前，先恢复原指数和对应 PDF。两边保留正常的热缓存；云端硬件、调度和全部包的具体版本没有受到控制。
- 此例只有一页，不含文献、图片或特殊宏。它不测冷构建、长文档、XeLaTeX 或 HTML 导出。

## 如何观察时间

本地观察器从编辑器中已提交的文本发生变化开始计时，等待新 PDF 的页面画布替换上一代画布。名义采样间隔为 10 ms，并核对新 PDF 文本中的指数。TeX 编译时间单独记录；编辑到 PDF 显示的时间包含保存、延迟、编译、PDF 加载与绘制。

Overleaf 使用真实的查找/替换界面。只读检查观察可见源码与 PDF 文本层，录像画面核实新指数已经显示。起点受界面操作前后两个时间戳约束，终点由前后两次旧/新 PDF 观测约束。因此报告区间，不编造精确时间；第 1 次的观测粒度比另外两次粗。两个产品的观测终点也略有区别。

Obsidian 使用 ScreenCaptureKit 的独立窗口录制；Overleaf 使用真实 CDP screencast，保留帧时间戳。对比图在每列中组合了同一帧的状态栏、源码和 PDF 裁剪，字幕位于应用画面之外。两段录制按观察到的编辑时刻对齐：本地已提交修改、Overleaf 界面操作区间的中点；保持正常速度。其他 GIF 展示完整窗格及跳转操作。

本次录制任务未在测量期间同时编码视频或运行测试。原片和详细本地收据保存在 Git 之外；[公开来源记录](showcase-provenance.json)保留片段范围与哈希。

Overleaf 官方说明[自动编译](https://docs.overleaf.com/getting-started/recompiling-your-project)每隔几秒运行，并在构建间保留辅助文件。此处比较包含这一用户可见流程，不能由总等待时间推算其服务端 TeX 执行时间。
