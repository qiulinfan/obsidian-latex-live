# LaTeX Live and Overleaf: different writing priorities

LaTeX Live brings native `.tex` projects into everyday reading and writing in Obsidian: read formulas and theorems in the source file, follow references in proofs to inspect statements and proofs, then use your own TeX toolchain to generate a PDF or self-contained reading HTML. Overleaf brings coauthors into the same paper through a browser, with editing, comments, review and history, reducing environment setup.

**Overleaf already offers a Visual Editor, automatic compilation, bidirectional SyncTeX, AI tools and HTML export.** LaTeX Live's differences should therefore be demonstrated through specific reading workflows and evidence of export fidelity; these capabilities are not exclusive to this plugin. [Editor](https://docs.overleaf.com/getting-started/how-do-i-use-overleaf), [SyncTeX](https://docs.overleaf.com/navigating-in-the-editor/working-with-the-pdf-viewer/moving-between-the-editor-and-pdf), [AI](https://docs.overleaf.com/integrations-and-add-ons/ai-features), [format conversion](https://docs.overleaf.com/managing-projects-and-files/importing-and-exporting-files).

Checked on **2026-09-30**. This compares LaTeX Live 0.1.0 in the current repository with Overleaf Cloud's documented public capabilities, rather than an authenticated experiment using the same manuscript. “Verified” refers to this repository's code, regressions and runtime records; “documented” refers to the linked current official pages; “inference” describes a judgment about workflow fit. Sources and unverified items are recorded in [overleaf-sources.json](overleaf-sources.json).

## Interpreting the performance numbers

| Local record | Result | Measurement boundary |
| --- | --- | --- |
| A 65-page Chinese ElegantBook fixture with math, theorems, tables, TikZ and bibliography; complete cold HTML export | 11.335 s, including 8.240 s for the complete build and 2.463 s for the probe | One synthetic project, including the complete PDF build. The 10 s cold target has not been reached. |
| Same project, with the complete build already fresh | 2.931 s; identical HTML and zero report items | Does not pay the complete TeX build cost again. This cannot replace the cold result or describe per-keystroke compilation time. |
| Native Obsidian, a 5891-line chapter with 16 arrow-key movements; another 20 movements inside a 190-line theorem | p95 6 ms / 6.2 ms | Small editing-response samples; not project compilation or popover expansion latency. |
| Proof-reference index for 5702 lines of source | Cold read 42.4 ms; cached read 0.7 ms | One Node data-service measurement, excluding card rendering, image loading and the complete UI. |

These are existing repository measurements, **not rerun for this review, and the same manuscript was not uploaded to Overleaf**. Hardware documentation and sampling are insufficient for a general cross-product benchmark. Overleaf's compile timeout is a plan resource limit; comparing a “10 s timeout” with an “11.335 s local export” does not identify a winner. [Local records](../design.md), [official limits](https://docs.overleaf.com/getting-started/free-and-premium-plans/plan-limits).

LaTeX Live is now open source under MIT; the current plugin code has no subscription allowance. Local hardware, environment maintenance, optional Obsidian services and external AI still have their own costs. [License](../../LICENSE), [current configuration](../../src/settings.ts). “No plugin subscription” therefore does not mean the whole workflow is cost-free.

**A stronger fit for LaTeX Live:** existing Obsidian users familiar with local TeX, primarily writing mathematical notes or theory papers independently, who want to read through theorems and proofs within the source and share a reading edition. **A stronger fit for Overleaf:** frequent coauthoring, online advisor comments, tracked review/history and publisher template entry points, or teams that do not want to maintain TeX for every author. Local `.tex` reading and Overleaf coauthoring can also coexist, with agreed synchronization and environment versions; the current plugin has no automatic collaboration protocol between the two.

A generic VS Code workflow can already provide local compilation, SyncTeX, completion and formula hover: these appear in LaTeX Workshop's official feature index. [LaTeX Workshop](https://github.com/James-Yu/LaTeX-Workshop/wiki/). The workflow worth demonstrating here is **reading-oriented live source in Obsidian → proof-reference popover → rich statements/proofs → portable reading HTML**. That is a positioning judgment, not an exclusivity claim about every VS Code extension combination.

The current boundaries should remain explicit:

- Chrome regressions and native Obsidian indexing/rich content were verified. Native-window footage on 2026-10-01 additionally records automated pointer hover, node clicks and content expansion. It does not replace OS-level cross-block drag verification or establish complete native UI acceptance.
- Untested templates/macros are not certified for semantic reading or HTML. Live citation chips remain author/year summaries, not every journal's citation style. Demonstrations should retain source/SVG fallbacks for complex drawings, the LuaLaTeX HTML limitation and the system-font body-text boundary.
- No authenticated Overleaf interaction, same-manuscript HTML fidelity/performance experiment or complete plugin accessibility certification was performed. The official index now lists [Working offline](https://docs.overleaf.com/writing-and-editing/working-offline), but its body could not be retrieved in this review. Browser behavior during brief disconnections and persistent offline use remains unverified; older material cannot establish that current offline editing is entirely unsupported.
